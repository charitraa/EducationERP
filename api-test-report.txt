BUGS FOUND BY THIS RUN (both fixed, with regression tests, then the whole run repeated)
----------------------------------------------------------------------------------------------------
  1. Failed-login error message was unreadable.
     Before: {"code": "invalid", "message": "[ErrorDetail(string='Invalid credentials or inactive
             account.', code='invalid_credentials')]"}
     After : {"code": "invalid_credentials", "message": "Invalid credentials or inactive account."}
     Cause : the error formatter turned a one-item list into its Python text form.
     Fix   : backend/core/common/exceptions.py. This affected any error raised the same way,
             not only login.
     Test  : core/authentication/tests/test_auth_api.py::test_failed_login_error_is_readable

  2. College admins could not see failed logins against their own users.
     Before: every failed-login audit entry had organization = NULL, so it never appeared in
             /api/v1/audit-logs/ for a college's admin — password guessing went unnoticed.
     After : the entry is filed under the account's organization (unknown emails stay
             platform-level, so nothing is revealed about who has an account).
     Fix   : backend/core/audit/signals.py
     Test  : test_failed_login_is_filed_under_the_accounts_organization

  Also corrected (mistakes in the test script, not the API):
   - Wrong-password login returns 400, as designed and unit-tested; the script expected 401.
   - Swagger page returned 406 because the script asked for JSON; asking for HTML gives 200.
   - "Teacher cannot list admissions" was wrong: in section 7 Ram legitimately gave Gita the
     Exam Office role at Lalitpur, and she saw exactly Lalitpur's two applications. The
     check now verifies that scope, and a staff-only user (Sita) is checked for 403 instead.
